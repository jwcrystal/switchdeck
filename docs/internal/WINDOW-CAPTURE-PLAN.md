# 視窗擷取與多視窗合成計畫

## 選區貼合調整

- 使用者確認設定視窗擷取已改善，進一步要求截圖區域貼合選取範圍。
- 單一視窗的畫布改為視窗實際邊界；多視窗使用所選視窗的最小外接矩形。不再為陰影自動外擴固定 28pt，也不改變手動框選的範圍。
- 擷取結果與編輯預覽沿用同一個畫布；螢幕邊緣只裁切越界部分，不縮放或重新置中視窗內容。陰影不得擴張畫布。
- 先驗證畫布尺寸與真正設定頁面輸出的選區，另以不對稱上下排列的影像驗證座標轉換，避免居中的舊測試掩蓋位置錯誤。
- 修正後重跑視窗合成、設定視窗選取與真實取圖、完整回歸及 Release 打包。
- 修正前的測試已確認：720×572pt 的設定視窗會被放大成 776×628pt 的選區；不對稱上下排列的視窗也會上下錯置。移除固定邊距並讓 CGContext 與視窗共用左下原點，避免重複翻轉 y 座標。
- 驗證完成：單／多視窗貼合、非對稱上下位置、螢幕邊緣裁切但不縮放及真正設定頁面的精確選區皆通過；啟用真實取圖的完整測試共 108 項（SwitchKit 18、Screenshot 90），零失敗。Release 打包、簽章、翻譯與 diff 檢查皆通過。

## 驗收修正：尚未達到參考效果

### 設定視窗修正結果

- 已重現並確認：`pid != ownPID` 使本程式設定視窗被跳過；`windowLayer == 0` 使浮動設定面板被跳過。修正為允許一般／浮動／模態面板，依精確 window ID 排除截圖浮層；透明或非應用視窗層級仍跳過。
- 螢幕／區域擷取不再排除整個 app，只排除截圖浮層 ID。每次解析這些 ID 時刷新 ScreenCaptureKit 清單，避免上一個 session 的快取漏掉新浮層。
- 明確選定視窗後，複製／儲存／釘選會等該視窗影像完成；擷取失敗不再靜默改抓桌面，也不漏掉多選集合中的視窗。編輯器顯示可重新選取的錯誤提示（英／繁中）。
- `WindowSelectionTests` 新增六項：自身設定視窗、浮動面板、立即輸出、失敗不回退、真實像素與浮層排除、真正 SwiftUI 設定頁面從點選到產出影像。修正前已看到錯抓背後 ID、設定像素被移除、立即輸出 base 為 nil、失敗回退桌面等測試失敗。
- 兩項真實取圖測試以 `SWITCHDECK_LIVE_CAPTURE_TESTS=1` 啟用，避免在沒有螢幕錄製權限的 CI 要求權限。其餘四項用可見測試視窗、WindowServer 清單與程式內 NSEvent 驗證，不依賴 Accessibility。
- 六項測試連續三次通過；真正設定頁面也已輸出 PNG 並檢視，確認取得設定內容，而非後面的視窗。這不是對同類工具全部視覺效果的驗收，也不宣稱完成實體滑鼠／鍵盤自動化驗收。
- 完整回歸（含啟用真實取圖）：SwitchKit 18 項、Screenshot 87 項，共 105 項，零失敗。繁中翻譯檢查、`git diff --check`、Release 打包與 codesign 驗證皆通過；CLI 診斷既有三處暫存 coordinator 的 weak-reference 編譯警告仍在，本輪未改動無關的生命週期問題。
- 測試指令：`SWITCHDECK_LIVE_CAPTURE_TESTS=1 swift test --filter WindowSelectionTests`。可加 `SWITCHDECK_CAPTURE_EVIDENCE_DIRECTORY` 將設定頁面的最終 PNG 留在指定本機資料夾，不存進 repository。

### 本輪具體問題與修正範圍

- 使用者已明確指出：必須能直接選擇程式視窗擷取，包含程式的設定頁面；目前視窗擷取流程不完整。本輪先修這條功能路徑，不擴充陰影、美化或其他工具。
- 重現方式：在測試程序建立真正可見的設定視窗（一般 NSWindow 與浮動 NSPanel），透過 `SelectionView` 的滑鼠事件選取，再檢查傳給視窗擷取回呼的 window ID；不靠 Accessibility 操作其他應用程式。
- 修正前先跑失敗測試；確認一般視窗／浮動設定面板／自身設定視窗的辨識規則。排除應針對擷取浮層，而非一律排除 app 全部視窗。
- 驗收涵蓋滑鼠指向時的可辨識高亮、點擊後確實走選定 window ID 的擷取回呼，以及最終輸出使用該視窗影像而非靜默改抓桌面。保留區域擷取與滾動停用行為。

- 使用者回饋：同類工具的視窗擷取效果較好，現有實作未跟上；不能因為接上視窗 API、合成器測試通過，就宣稱效果等同或架構較好。
- 前文對那類快照、刷新與排序機制的描述主要來自靜態名稱，未驗證實際執行路徑；下方「不搬」等限制是早期設計選擇，不是已驗證的必要取捨。後續以實際效果與證據決定，不先排除方案。
- 驗收必須比較同一個視窗：選取與編輯預覽、輸出視窗的位置與尺寸、內容方向與清晰度、圓角透明區、陰影及螢幕邊緣；多視窗另驗證前後遮擋順序。
- 一般合成單元測試與 CLI 取圖不代表完整 GUI 流程已驗收，也不代表已追上參考效果。
- 本輪桌面自動化檢查：Screen Recording 已授權，但 agent-desktop 的 Accessibility 權限被拒絕。尚無同一視窗的成對參考樣本，不能聲稱已重現使用者所見的差距。
- 修改程式前先取得具體失敗樣本或可操作的 GUI 重現流程，再建立能針對該差距失敗的檢查；不以猜測替代視覺驗證。

## 原始方案（以下有更新之處，以本輪修正結果為準）

- 日期：2026-11-13
- 觸發：目前「視窗」只是 `CGWindowListCopyWindowInfo` 吸附出的矩形，像素仍從整屏裁切。壓在上面的其他視窗會一起入鏡，也沒有陰影。參考做法是逐視窗取內容，再依需求合成。
- 決策：沿用現有一次取幀模型，加入單視窗與多視窗合成；不改造成常駐快照／視窗排序引擎。

## 目標

1. 點擊視窗時，只取該視窗的內容，不受其他視窗遮擋，並帶柔和陰影。
2. `⇧` 點擊可加入多個視窗；合成時依它們在螢幕上的相對位置排列，共用一個畫布。
3. 保留既有的區域、全螢幕、延遲、標註、複製、儲存與釘圖行為。

## 不變

- 區域與全螢幕仍走 `captureRegion` / `captureDisplay`，用 `SCContentFilter` 排除截圖浮層，不排除自身設定視窗。
- 只有進入編輯時才抓幀；延遲擷取仍先凍結畫面。
- 不新增設定項、不改儲存格式與檔名規則。
- 滾動截圖維持停用。

## 互動

- 懸停視窗：虛線高亮該視窗。
- 點擊視窗：選取該視窗，畫布貼齊視窗實際邊界，直接進入編輯。
- `⇧` 點擊視窗：加入／移除待合成清單，先不進編輯；按 `Return` 或再點清單內的視窗才進編輯。
- 拖曳、`R`、`F`：清空待合成清單，回到既有的區域／全螢幕行為。
- `Esc`：有待合成清單時先清空；否則照舊關閉。
- 待合成時顯示「N 個視窗 · Return 編輯 · Esc 清除」。

## 幾何

- 所有矩形都用螢幕區域座標（左下原點），與 `SelectionView` 一致。
- 畫布 = 所有視窗框的聯集與螢幕邊界的交集，不額外外擴；螢幕邊緣只裁切越界像素，不縮放內容。
- 合成 context 以 `scale = 螢幕 backingScaleFactor` 建立，逐窗以原生像素畫入；超出畫布的部分自然裁掉。
- 陰影由合成器自己畫（`NSShadow`，位移向下、模糊與不透明度固定），不採用 ScreenCaptureKit 的內建視窗陰影，避免它把視窗內容縮小以容納陰影。
- 視窗影像本身的圓角透明區保留；PNG／HEIC 存檔保留透明背景，JPEG 由 ImageIO 襯白。

## 抓取

- `ScreenCaptureService.captureWindow(windowID:)` 改用視窗所在螢幕的 scale（原本固定用第一個螢幕），並設定 `ignoreShadowsSingleWindow = true`。
- `SCShareableContent` 快取命中就直接用；找不到視窗時強制刷新一次，避免新開視窗因為 20 秒快取而抓不到。
- 任一選定視窗抓取失敗即停止該次視窗輸出並顯示提示，不跳過視窗，也不改抓整屏裁切。

## 測試與驗收

- `swift test`：新增合成器測試，既有 104 項不得退步。
- 以 CLI 或實際 GUI 抓一個視窗，確認輸出只有該視窗內容、有陰影、透明角落正確。
- 多視窗以兩個不重疊視窗確認相對位置與畫布大小。
- 視窗關閉或抓取失敗時，不輸出其他視窗／桌面影像，顯示可取消重選的提示。

## 不做事項

- 不搬常駐視窗快照佇列、非同步視窗排序修正，也不在抓取前強制刷幀。
- 不做視窗陰影強弱、背景桌布、圓角等美化設定。
- 不做跨螢幕多視窗合成；一次合成只處理同一個 overlay 螢幕上的視窗。
